# Prepared physical rows for Flash-Next attention

2026-11-07, gfx1151. **Retained, undeployed operator candidate.** The model,
quantization, arithmetic and serving baseline are unchanged. This is not a
measured whole-model throughput improvement.

The [attention trace](../strata-attention-replay/README.md) exposed dependent
selected-ID/page-table lookups. This experiment computes a 64-bit physical
KV row once per query/selection, then shares that row across the attention
heads. A GPU preparation pass and its scratch traffic are included in timing.
Missing/nonresident/padded cells have sentinel -1. The scratch stores the
KV-head-zero base; attention adds the appropriate head's page offset.

## Results

Off/on/on/off processes, gated FP16 output, default trim/read-prefetch,
synthetic Q/K/V values with real captured selection distributions. Each 4K
process reports a median of 31 repetitions; full 16K uses 15. Compare the
mean of the two process medians for each arm:

| Replay | Control | Prepared, including setup | Operator speedup |
|---|---:|---:|---:|
| Layer 0, final 4K queries | 22.086 ms | 21.553 ms | 2.47% |
| Layer 3, final 4K queries | 22.910 ms | 21.9415 ms | 4.41% |
| Layer 7, final 4K queries | 24.1745 ms | 23.1055 ms | 4.63% |
| Layer 7, full 16K chunk | 90.5265 ms | 87.7535 ms | 3.16% |

Full-chunk control process medians were 90.047 / 91.006 ms; prepared medians
87.687 / 87.820 ms. Preparation alone cost 1.993 / 1.989 ms and is already
included. All outputs matched bit for bit. The full-chunk output hash was
`9d7703748fff2383`; the 4K hashes match the earlier gated controls.

Attention still uses 200 VGPRs, 18,432 LDS bytes, no scratch spills. The
preparation kernel uses 16 VGPRs and no LDS/scratch. Its separate buffer is
**268,828,672 bytes (~256.4 MiB)** at 16,384 queries × 2,051 selections.
This extra allocation and production lifetime remain to be integrated and
measured. With attention about 10% of prefill, a uniform 3.16% operator
speedup would predict only about 0.3% overall (~4 tok/s at 1,400). That is an
estimate, not a full-model result. Retain repeatable small wins and combine
only after measuring their individual and joint effect.

## Correctness and boundaries

24 off/on pairs passed exact output comparison, CPU physical-row mapping,
the prepared-buffer guard and padded-output guard:

- Identity, shuffled, partially missing and entirely missing page tables.
- Original widths and mixed 0/1/31/32/33/cap widths; unused IDs poisoned.
- Fast FP16 and split-precision attention paths.
- Query counts 1, 31, 32, 33 and 64, first/final page boundaries.
- 65,536 queries at cap 1, crossing the wrapper's 65,535-query dispatch split.

These test address ownership and preserve the existing operator result;
they are not a CPU numerical attention reference or model/state validation.
No arithmetic decode change is combined with this experiment.

## Reproduction and promotion boundary

Use pinned source v0.2.11 `c3b3f5035506f3e966f1b4b7b188aeaabae92f1d`
and the [lab build setup](../strata-expert-profile/README.md). Apply the
earlier `strata-attention-replay/gated-replay.patch`, then this directory's
[prepared-rows.patch](prepared-rows.patch). The latter was recorded as local
source commit `41021fb` on top of `16834dd`; neither commit is on upstream.
Build `hip_pa_bench`. No expert patch is needed for this attention test.

```sh
STRATA_HIP_WMMA=1 STRATA_PA_FAST=1 STRATA_PF_SWITCH_MIN_T=4096 \
  PA_BENCH_GATE=1 PA_BENCH_ROWS=0 "$BUILD/hip_pa_bench" /tmp/layer7.bin 31
STRATA_HIP_WMMA=1 STRATA_PA_FAST=1 STRATA_PF_SWITCH_MIN_T=4096 \
  PA_BENCH_GATE=1 PA_BENCH_ROWS=1 "$BUILD/hip_pa_bench" /tmp/layer7.bin 31
```

Use the earlier published `record-019-layer-07-pos-61440.bin.gz` for the 4K
test. The full-chunk record is index 19 of the completed public capture;
it remains local (134.7 MB) and can be regenerated by the earlier capture
procedure. Compressed boundary fixtures and all per-case settings are in
[the evidence](../../evidence/strata-performance-2026-11-07/attention-rows/).
For each correctness row, unpack its fixture and run both `PA_BENCH_ROWS`
values with the recorded `PA_BENCH_PAGES`, `PA_BENCH_WIDTHS` and
`STRATA_PF_SWITCH_MIN_T`; one timed repetition is sufficient for hash/guard
verification. Retain the enabled gate and other environment settings above.

The new preparation/attention entrypoints are called only by the replay
harness. Production prefill has no selector or allocation for them yet.
Unsupported trim/read-prefetch settings fall back to the existing ID reader.
Before promotion: integrate an independent opt-in production allocation,
build the full engine, measure complete cold requests including memory cost,
and pass state/continuation and tool-use checks. Only HIP was built here;
build all affected backends before any upstream submission.
